# Moldability draw-axis benchmark — built-in difficulty ladder (plan (c))

Generated by `python -m moldability.bench` on the analytic T0–T3 ladder.
The **oracle** (exhaustive verifier sweep) is the ground-truth reference; each
method is scored by the metrics a mold shop cares about. This analytic set is a
*smoke test* — it discriminates a real draw-axis search from bbox-aligned
heuristics; discriminating SFTF vs PCA needs real parts (`bench --folder ...`).

## How to read this

- **rect_tube_rotated is the discriminator.** Its moldable axis is off the X/Y/Z
  grid. `bbox6` misses it — its best axis among X/Y/Z needs **2 side actions vs
  the oracle's 0** (`match = .`, `uc ratio = inf`) — while `sftf_warmstart` and
  `pca` recover the true 0-side-action axis. This is the industrial point: a
  bbox-aligned heuristic over-quotes tooling on an off-axis part.
- **R2 removed the *false* die-lock here.** Before the hemisphere pull search,
  `bbox6`'s best X/Y/Z axis was flagged **die-locked** (`die-lock ok = .`) because
  a flat-ring search could not free the *tilted* bore — the part looked like it
  needed a redesign. The lifter-aware search now frees that bore with an angled
  pull, so `die-lock ok = Y`: bbox6's error is honestly an over-count of side
  actions, not a spurious die-lock. (This is why bbox6's `SA ±1` dropped to 0.80.)
- **`mean calls` is not the budget story.** The cheap heuristics make only 3
  verifier calls but are wrong; `sftf_warmstart` spends more verification to be
  correct. Its meaningful *budget* is calls / a full **1° sweep** (single-digit
  %); the `calls` column here is against a coarse 200-axis oracle, not a fine
  sweep, so it understates the saving.
- **PCA ties SFTF here only because tubes are elongated** (principal axis = tube
  axis = moldable axis). On real parts where the moldable axis is *not* the
  principal axis, this is where SFTF should separate from PCA — that test needs
  the Thingi10K / real-part set (BUILDSPEC R7).
- **die-lock recall = 1.0 for all methods** only because the sealed shell is
  die-locked from *every* axis, so even 3 probes catch it. A part die-locked on
  only some axes would separate the methods on recall too.
- **side actions count only *buildable* slides** (R1: minimum set-cover over
  compatible pull directions). The sealed shell therefore shows `SA = 0` *with*
  `die-lock ok = Y`: there is no feasible side action to build — the part needs a
  redesign, not a slide. This also means two undercuts freed by one shared pull
  count as **one** side action, and one cluster needing two pulls counts as **two**
  (see the `two_perp_undercuts` / `twin_parallel_undercuts` acceptance tests).

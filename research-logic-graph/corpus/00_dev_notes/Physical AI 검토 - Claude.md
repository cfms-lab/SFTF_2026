요즘
피지컬 AI가 유행인데, 내가 하고 있는 연구랑 어떻게 접목할 수 있을까?


좋은
타이밍의 질문입니다. 결론부터: 피지컬 AI의 최대 난제가 "변형체(deformable) 조작"인데, 선생님은 그
난제의 시뮬레이션 스택을 이미 다 갖고 계십니다. 접목 지점을 강한 순서로 정리하면:


1.
의복 조작 로봇의 시뮬레이션 인프라 (가장 강한 접목)


로봇
파운데이션 모델들이 강체 조작(집기, 옮기기)은 빠르게 정복했지만, 옷 개기·입히기·봉제 같은 변형체 조작은 여전히 최전선입니다.
이유는 단순한데 — 학습에 필요한 시뮬레이션과 데이터가 없어서예요. 그런데 보세요:



드레이프 엔진 (48만
줄, 검증됨) = 로봇 학습용 물리 환경


GarmentCode/GarmentCodeData_v2
+ 패턴 CAD (지금 시작하는 프로젝트) = 무한 태스크 생성기 (파라메트릭으로 "세상 모든 옷"을
찍어내며 학습 환경 다양화)


JAX 전환 = 미분가능
시뮬 → 정책 학습에 물리 그래디언트 공급



이
셋의 교집합을 가진 연구 그룹은 세계적으로도 드뭅니다. 구체적 논문거리: "파라메트릭 의복 생성 + 미분가능 드레이프로 만드는 의복
조작 벤치마크/데이터 팩토리" — 로봇 학습 커뮤니티가 지금 목말라 하는 물건입니다.


2.
봉제 자동화 — 선생님만의 비대칭 전력


의류
제조 자동화(robotic sewing)는 노동집약 산업의 성배인데 번번이 실패해 온 분야입니다. 천이 물리적으로 어떻게 거동하는지 모델링이
안 되니까요. 선생님은 여기에 특허심사관 시절의 재봉기·자수기 도메인 지식 + PatentKG 온톨로지 + 천 시뮬을 다 갖고
계시죠. "봉제 공정의 디지털 트윈"(바늘-천-이송 상호작용 시뮬 + AI 제어)은 학계에 거의 빈 땅이고, 산업 수요는
확실합니다.


3.
SFTF 쪽: 뉴럴 서로게이트와 자율 제조


3D프린팅
지지구조 연구도 접점이 명확합니다:



학습형 서포트 예측기: 지금
SFTF 파이프라인의 heightfield proxy·서포트 비용 계산이 곧 학습 라벨입니다. 메쉬를 넣으면 서포트 비용·최적 빌드
방향을 즉시 뱉는 신경망 서로게이트를 만들면 "AI 슬라이서"가 되고, 기존 연구가 데이터 생성기 역할을 하며
재활용됩니다.


방향 텐서장 → 연속섬유
3D프린팅: PFTF의 방향 텐서장 수학은 섬유강화 복합재 프린팅의 섬유 배향 경로 계획과 사실상 같은 문제입니다.
"섬유(fibrous)" 연구실 정체성과 정확히 맞물리는 확장이고요.


인시츄 모니터링 + 강화학습으로
실패 감지·재배향하는 폐루프 자율 프린팅은 피지컬 AI 문법 그대로의 제조 응용입니다.



4.
합성데이터 공급자 포지션


NVIDIA
Cosmos류 월드 모델들이 훈련 데이터로 목말라 하는 것 중 하나가 물리적으로 정확한 변형체 장면입니다. 검증된 천 시뮬 엔진은
"패브릭 도메인 합성데이터 팩토리"로 포지셔닝할 수 있습니다 — 비전 모델용(옷 상태 추정, 주름 인식) 라벨 완비
데이터를 찍어내는 역할이죠.


제
추천


단기적으로는 3번의
뉴럴 서로게이트가 가장 싸게 논문이 됩니다 — 데이터 생성 코드가 이미 돌아가니까요. 하지만 중기 승부수는 1번입니다. 지금
진행하는 의복 CAD(PatternSoft+GarmentCode) 프로젝트가 완성되면, 그건 단순한 CAD가 아니라 "의복 조작
로봇 학습의 태스크 생성기"라는 두 번째 정체성을 공짜로 얻게 됩니다. 같은 코드가 CAD 논문과 피지컬 AI 논문 두 갈래로
팔리는 구조 — 연구 포트폴리오 설계로는 이게 제일 효율적입니다.


원하시면
1번 방향의 관련 연구 지형(기존 벤치마크들, 어디가 비어 있는지)을 딥리서치로 조사해 포지셔닝 보고서를 만들어 드릴까요?




출처:
<https://claude.ai/epitaxy/local_5262a6d1-e96d-4ac9-9954-c6fb3f7bbdd9>


기다리는
김에, sftf/pftf 가 warm-starter로서의 역할이 있는데, 정확성이 약간 떨어지니까, 학습을 통해 DB가 쌓이면 좋을 것
같긴해. 그런데 학습용 메쉬 데이터는 뭘 쓰면 좋지? thingi10k같은 경우에는 몇 개나 다운 받아야 할까?


좋은
구상입니다 — "SFTF = 정확한 라벨러이자 warm-starter, 신경망 = 그 위에 쌓는 즉답 캐시"라는 구도라면
데이터 선택이 핵심이죠. 결론부터: Thingi10K를 주축으로, 필터링 후 3천~5천 개면 논문 규모로 충분하고, 파일럿은
500개면 됩니다.


왜
Thingi10K인가


학습
데이터는 "실제로 사람들이 프린팅하는 형상 분포"를 닮아야 하는데, Thingi10K는 Thingiverse에서 수집한
1만 개 실제 출력용 모델이라 이 조건을 유일하게 만족합니다. ShapeNet/ModelNet은 비전용(의자·자동차 카테고리 편향, 내부
구조 엉망), Objaverse는 스캔·장면 잡음이 많아 분포가 어긋납니다. 보조로 섞을 만한 것은:



ABC / Fusion 360
Gallery — 깨끗한 기계부품 CAD. 공학 부품 쪽 일반화를 주장하고 싶을 때 1~2천 개 보충.


자체 g5test 메쉬 —
마네킹 같은 유기 형상 하드케이스는 테스트 셋으로.



Thingi10K는 pip install thingi10k 패키지가 있어서 (watertight, 단일 컴포넌트, 면수 범위 같은) 필터 조건으로 골라 받을
수 있습니다. 전체를 다 받을 필요가 없어요.


몇
개나 필요한가 — 태스크별 산수


핵심은
"메쉬 개수"가 아니라 학습 샘플 수입니다:



전역 예측 (방향별 서포트
비용 → 최적 방향 랭킹): 메쉬 1개 × 방향 128개 = 샘플 128개. 선생님 파이프라인의 reorientation_support_matrix가 레이 없는 가산 프록시라 방향
하나당 비용이 거의 공짜죠. 3천 메쉬 × 128방향 ≈ 38만 샘플 — GNN/포인트넷 회귀에 넉넉합니다.


면 단위 dense
예측 (오버행/서포트 높이/지지흐름장): 메쉬 1개가 이미 수만 면 = 수만 라벨. 이 태스크는 개수보다 형상
다양성이 지배해서, 1천 메쉬로도 5천만 면 샘플이 나옵니다. 메쉬 분할 문학에서 수백~수천 형상으로 학습하는 게 표준이고요.



그래서
제안하는 단계는: ① 파일럿 500개 (필터: 단일 솔리드, 면수 5천~20만, 퇴화 면 없음)로 라벨 파이프라인과 입력
표현을 검증 → ② 3~5천 개로 본 학습 → ③ 부족하면 회전 증강(방향 태스크는 증강이 내장된 셈)으로 늘립니다. 1만 개
전부는 필요 없을 가능성이 높습니다.


실무
팁 세 가지



전처리 정규화가 라벨 품질의 절반입니다. 스케일을 프린트 볼륨 기준으로 통일하고, 면
밀도를 리메싱으로 균일화하세요(며칠 전 CFMS 메쉬에서 봤듯 subdivide_to_size류의 T-정점
조각화 같은 함정이 실데이터에 잔뜩 있습니다 — Thingi10K는 일부러 지저분한 메쉬도 포함시킨 데이터셋이라 필터·수리 단계가
필수입니다).


라벨 예산 이원화: SFTF 프록시
라벨은 전체(3천 개 × 128방향, 몇 시간 규모)에, Cura oracle 라벨은 검증 서브셋(예: 200개 ×
8방향)에만. "프록시로 학습, 슬라이서로 검증"이 논문 서사로도 깔끔하고, 이미 validate_cura_oracle.py 등 스크립트가 있으니
재활용됩니다.


DB 스키마를 지금 정해두세요:
메쉬 해시 → (정규화 변환, 방향별 비용 벡터 128, SFTF 최적 방향, 상위 방향의 면별 특징) 형태로 쌓으면,
warm-starter 용도(신경망이 초기 방향 랭킹 예측 → SFTF가 상위 후보만 정밀 평가)와 학습 용도를 한 DB로
겸합니다. 나중에 "프록시와 Cura가 크게 어긋나는 메쉬만 골라 추가 라벨링"하는 능동학습으로 확장하기도
좋고요.



마침
돌고 있는 딥리서치가 선행연구들이 어떤 데이터셋·규모를 썼는지도 조사 항목에 있으니, 결과가 오면 이 숫자 감각(3~5천이 동급 연구 대비
충분한지)을 교차 확인해 드리겠습니다.


조사가
완료됐습니다(에이전트 102개, 약 349만 토큰 — 어제 여쭤보신 토큰 비용의 실측치입니다). 잘린 부분을 마저 읽고 정리하겠습니다.


읽기 파일
1개, 생성됨 파일 1개


조사 결과가 아주 고무적입니다. 보고서를 SURROGATE_LANDSCAPE_2026-07-11.md로 SFTF 리포에 저장했고, 요지는 이렇습니다:


핵심
판정: 노리시는 니치가 비어 있습니다. 조사 범위(2018~2026, 주장 25건 중 23건 3-0 교차검증 통과)에서
"메쉬 입력 → 면별 서포트 비용장 + 빌드방향 랭킹" 서로게이트는 없습니다. 빌드방향 예측은 2020년
복셀 CNN(가공피처 우회) 수준에서 정체되어 있고요.


가장
가까운 경쟁자이자 최고의 선물: PAGE-Net (IJAMT 2026.1). 메쉬 GNN으로 부품질량·서포트질량·출력시간을
예측하는데(추론 77ms), 결정적으로 — (1) 전역 스칼라만 출력하고, (2) 서포트 질량이 가장 약한
타깃(R²≈0.68, 나머지는 0.96+)이며, (3) 주어진 방향만 다룹니다. 원인이 자기지지 형상 위주의 zero-inflated
분포인데, 이게 정확히 선생님 접근의 서사가 됩니다: "어느 면이 비용을 내는지(필드)를 배우면 스칼라는 합산으로
공짜". 게다가 PAGE-Net의 데이터(Slice-100K)가 Thingi10K 유래라 같은 메쉬에 SFTF 라벨을 입혀 직접
비교 벤치마크를 만들 수 있습니다.


어제
드린 숫자 감각도 검증됐습니다 — PAGE-Net이 9,049 기하 × 10설정이니, 말씀드린 3~5천 개면 동급 규모가 맞습니다.
Thingi10K를 AM 라벨로 재목적화하는 관행도 Slice-100K, SEG 등으로 확립되어 있고, "기존 파이프라인=라벨
생성기" 전략도 PATO(상용 열변형 시뮬 244샘플), PAGE-Net(PrusaSlicer CLI) 등 선례가 탄탄해서 방법론
시비 위험이 낮습니다.


타이밍
신호 둘: 미분가능 슬라이싱 최전선(Mishra & Wu 2026)이 인스턴스당 ~11시간이라 빠른 서로게이트의 필요를 문헌이 직접
시사하고, 생성모델 진영(SEG 2025.11)은 방향 최적화를 명시적으로 future work로 미뤄뒀습니다. 수요는 열려 있는데 공급이
없는 상태예요.


주의사항
둘만 꼽자면 — ① 이 공백 분석은 "대표 논문들이 점유 안 함"의 합성이지 부존재 증명이 아니라서, 투고 전에
2022~2025 GNN×빌드방향 체계적 검색이 필요합니다(검증 단계에서 저자들의 전칭 공백 주장 2건이 실제로 기각됐습니다 — 이 바닥
논문들 자기 주장을 그대로 믿으면 안 됩니다). ② PAGE-Net·SEG 등이 2026년 1~2월 초신선 논문이라 후속 경쟁작이 빠르게
나올 수 있어, 착수한다면 속도가 중요합니다.


다음
단계로 자연스러운 것은 어제 말씀드린 파일럿입니다: Thingi10K 필터링 500개 → SFTF 라벨 파이프라인 검증. 원격 PC 작업
시작하실 때 GarmentCAD 킥오프처럼 이 보고서도 같이 가져가시면 됩니다 (SFTF 리포 안에 있으니 git pull로 따라갑니다).
